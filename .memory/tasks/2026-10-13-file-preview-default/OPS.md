- Mechanism for the source-view default (two independent causes):
  1. `resolveFileOpenMode` returned `"preview"` for markdown only when the globally persisted `codexweb.fileNonDiffMode` was `"preview"` (default `"file"`), and `setFileViewMode("file")` rewrote that key on every non-previewable open, so the preview preference could not survive an unrelated file open.
  2. `openReference` (`app_file_viewer.js`) hardcoded `mode: "file"` for every transcript file link, which set the global mode to `file` before resolution ran.
- Verified HTML has no preview path at all: server kind vocabulary is `image|pdf|video|download_only|directory|markdown|text` (`file_types.file_kind`, `file_text.markdown_kind`), `currentFileModeControlState` revealed the preview control only for `kind === "markdown"`, and `_send_preview_blob` refuses non-media kinds (400 "file is not previewable inline").
- Measured facts that fixed the design: auth cookie is `SameSite=Strict` (`codoxear/auth.py:114`) so a sandboxed opaque-origin frame would 401 every relative subresource → the frame needs `sandbox="allow-same-origin"`; `urlparse` path is not unquoted by `server_handler`, so a raw path route must decode segments itself; `CONTENT_SECURITY_POLICY` is applied to static responses, not to file routes.

## 2026-10-13T17:0x+08:00 — browser verification found a real routing defect (fixed)

- Dispatched the Docker browser verifier (`scripts/docker_file_preview_verify.sh`, committed by that agent as `746b2f43`), which drives transcript file-ref links, the file picker, the source toggle, and a changed-file diff through Chromium against a container built from a git archive of the commit.
- Result against `7321f33d`: markdown preview PASS (rendered heading, no Monaco, preview button active), source toggle PASS, picker→`src/main.py` source PASS, picker→changed `README.md` diff PASS, line-targeted `notes.md:3` source PASS. **HTML preview FAIL**: the iframe had `sandbox="allow-same-origin"` with scripts blocked, but its document request `/api/sessions/broker-44/file/raw//workspace/demo/report.html` returned the Python `http.server` default 404 page (`Error code explanation: 404 - Nothing matches the given URI.`), so the heading, the relative PNG, and the stylesheet were all absent.
- Root cause (found by reading the dispatch order, not by guessing): `server_handler.do_GET` runs `_handle_static_get` **first**, and `static_route_asset` falls back to "any path whose suffix is servable is a static file" (`rel = path.lstrip("/")`, suffix in `STATIC_SERVABLE_SUFFIXES`) so that a newly added frontend module cannot fall through to the SPA fallback. `send_static_file` then misses the file under `static/` and calls `send_error(404)`. The new raw route's URL necessarily ends in the document's own suffix (`.html`, and its subresources in `.png`/`.css`/`.js`/`.svg`/`.json`), so the static handler answered every preview request with a 404 before the API chain ran. The existing media routes never hit this because they carry the path in the *query* (`/file/blob?path=x.png`), which is why the collision was novel to this design.
- Reproduction of the routing decision without a browser: `static_route_asset("/api/sessions/s/file/raw/docs/report.html")` returned the path as a static rel (→ 404) before the fix and `None` after it.
- Fix: `static_route_asset` returns `None` for `/api` and `/api/...` before the servable-suffix fallback — the API namespace belongs to the API route chain. Tests: `test_static_route_asset_never_claims_the_api_namespace` (seven document/asset suffixes including the absolute-path double-slash form) and `test_static_get_route_declines_document_preview_urls` (dispatch-level `False`, plus the fallback still serving a genuinely new top-level module).
- The unit tests that passed silently were direct `handle_file_get_route` calls, which bypass the dispatcher; the browser run is what exposed the gap. That is why the new test sits at `handle_static_get_route`, the decision point that actually swallowed the request.
- Verifier also reported `agent-browser errors` rows `Canceled` (x2) and Monaco's `TextModel got disposed before DiffEditorWidget model got reset` when the script switched files rapidly. Not attributed to this change: the app aborts in-flight loads by design (`AbortController`) and re-creates editors per open. To be re-checked in the re-run for whether they appear when only one file is opened.
